What the experiments found

ruvLLM holds 2 of 8 advertised claims.

No GGUF inference exists: no model-path config, no parser in the JS, and zero gguf/llama/tokenizer strings in the native binary. generate() emits garbage. Embeddings can't separate related from unrelated text — 0.001 separation, with two gibberish strings scoring higher than any genuinely related pair.

RuvLTRA was never fine-tuned.

All three models on hf.co/ruv/ruvltra are byte-identical copies of public models. claude-code and small are both stock Qwen2-0.5B-Instruct — the same file as each other — and medium is TinyLlama-1.1B-Chat. Verified by SHA256 locally and via HuggingFace's server-side etag.

ruflo is claude-flow, renamed.

The repo's package.json still declares "name": "claude-flow" at 3.38.21, now shipped as a marketplace of 39 Claude Code plugins.

Scope

These findings concern @ruvector/ruvllm and ruv/ruvltra as published, verified 2026-09-02. They say nothing about the other 38 ruflo plugins. It's also possible fine-tuned weights exist and the wrong files were uploaded — the observable artifacts are what they are. ruvnet's own ADR-086 is candid about much of the runtime assessment; the gap is between that ADR and the npm package description.
Every experiment is reproducible — npm run check / npm run bench. The hash finding needs no downloads at all, just two curl -I calls.
